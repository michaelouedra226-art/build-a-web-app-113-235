CAHIER DES CHARGES — Site vitrine MAISON SILLAGE

Parfumerie sur-mesure · Version 1.0

CONTEXTE & PRÉSENTATION

Élément Détail
Client MAISON SILLAGE
Activité Parfumerie de niche sur-mesure — création de fragrances personnalisées, collections signatures, ateliers olfactifs
Positionnement Haut de gamme / luxe accessible — savoir-faire artisanal, matières premières nobles, expérience sensorielle unique
Projet Refonte complète du site vitrine existant (WordPress) vers une stack moderne, performante et évolutive
Objectif business Générer des rendez-vous découverte (sur-mesure), vendre les collections signatures en ligne (redirection boutique), asseoir l'autorité de marque
Langue Français (v1) — architecture prête pour EN / ES ultérieurs
Devise EUR
Zone France métropolitaine (livraison), international (boutique physique Paris, ateliers sur réservation)

Contexte concurrentiel

Le marché de la parfumerie de niche est en forte croissance (+12%/an). Les acteurs installés (Diptyque, Le Labo, Byredo) dominent la notoriété mais offrent peu de personnalisation réelle. Les nouveaux entrants "sur-mesure" (Sillages Paris, Olfactive Studio) misent sur le digital-first mais manquent de légitimité artisanale. MAISON SILLAGE occupe une position unique : atelier physique parisien + nez titulaire + matières premières sourcées en direct. Le site doit traduire cette singularité sans tomber dans le vocabulaire marketing générique ("artisanal", "unique", "d'exception").

2.2 Objectifs de perception

  • Installer la crédibilité artisanale dès la première vue (hero, matières, gestes du nez)
  • Différencier radicalement de l'e-commerce parfum standard : pas de "panier", pas de "promo", expérience éditoriale
  • Donner envie de pousser la porte de l'atelier (physique ou virtuel)

2.3 Objectifs techniques

  • Score Lighthouse ≥ 95 sur les 4 piliers (Performance, Accessibilité, Best Practices, SEO)
  • Core Web Vitals dans le vert (LCP < 2.5s, INP < 200ms, CLS < 0.1)
  • Zéro dépendance lourde côté client (pas de bundle JS > 150ko gzippé hors vendor)
  • Déploiement continu sur Vercel, preview automatique sur chaque PR

PÉRIMÈTRE

Dans le périmètre (MVP v1.0)

  • Accueil éditoriale + hero immersif
  • Page /maison (histoire, nez, atelier, valeurs)
  • Page /collection (grille parfums + fiches détaillées)
  • Page /sur-mesure (processus 4 étapes + formulaire RDV)
  • Page /journal (articles, carnets de création, actualités)
  • Page /contact (infos, formulaire, plan d'accès)
  • CMS Sanity (contenus, médias, SEO, JSON-LD)

Hors périmètre (explicite)

  • E-commerce complet (panier, paiement, comptes clients, expédition)
  • Espace client / tableau de bord
  • Configurateur de parfum interactif en temps réel (V2)
  • Programme fidélité / abonnement
  • Marketplace revendeurs
  • Application mobile native
  • Multilingue actif (architecture prête seulement)
Note

La redirection vers la boutique en ligne (Shopify existant) se fait via boutons "Voir sur la boutique" sur les fiches collection. Aucun traitement de commande sur le site vitrine.

Page Contenu clé
/maison/histoire Chronologie interactive (années + jalons), texte long, images d'archives
/maison/le-nez Biographie, philosophie, formation, matières favorites, vidéo courte (portrait)

6.3 /collection + fiche parfum

Page grille : filtre par famille olfactive (6 familles), tri (nouveauté, best-seller, prix). Carte : image, nom, famille, note de tête, prix "À partir de", tag "Sur-mesure possible".

Fiche (/collection/[slug]) : galerie 3 images (flacon, matière, ambiance), pyramide olfactive interactive (hover/tap révèle description matière), texte de création (histoire du parfum), formats disponibles (30ml, 50ml, 100ml, extrait), bouton "Voir sur la boutique" (lien externe Shopify), bouton "Personnaliser" → /sur-mesure, produits suggérés (3 max).

6.4 /sur-mesure — Processus 4 étapes

  1. Diagnostic olfactif — Questionnaire en ligne (12 questions : goûts, souvenirs, occasions, budget, allergies). Résultats : 3 profils suggérés + rdv conseillé.
  2. Création en atelier — RDV 2h avec le nez. Sélection matières (organoleptique), premières formules, ajustements. Traçabilité lot matière.
  3. Essais & Ajustements — 3 essais maximum sur 4 semaines. Envoi échantillons (pipettes 2ml) + fiche de retour. Ajustement final validé par client.
  4. Livraison & Suivi — Flacon gravé (nom + date), coffret, certificat d'authenticité (numéro de lot, formule archivée). Relance 6 mois (évolution parfum).

6.5 /journal

Liste paginée (12/articles), filtre par catégorie (Carnets de création, Matières, Événements, Coulisses). Carte : image, catégorie, titre, date, temps de lecture, extrait. Article : hero image, méta (auteur, date, catégorie, lecture), corps riche (images, citations, vidéos embed), articles liés (3), partage social, newsletter CTA.

6.6 /contact

Informations : adresse (atelier + boutique), horaires, téléphone, email, plan interactif (Mapbox/Leaflet, pas Google Maps), formulaire (voir 6.7), FAQ lien, mentions légales liens.

7.5 Animations

  • Durée standard : 200ms (micro-interactions), 400ms (transitions de page/chargement)
  • Easing : cubic-bezier(0.25, 0.46, 0.45, 0.94) (material standard)
  • Respect prefers-reduced-motion : désactiver tout mouvement non essentiel
  • Scroll reveal : IntersectionObserver, seuil 0.1, rootMargin "0px 0px -50px 0px"
  • Hero vidéo : lecture auto muette, pause hors viewport
  • Pas de parallaxe complexe, pas de Lottie, pas de GSAP — Framer Motion uniquement pour transitions de layout et AnimatePresence

8.3 Implémentation

  • Chaque icône = composant React TypeScript individuel (IconFlacon.tsx)
  • Props : size?: number (défaut 24), strokeWidth?: number (défaut 1.25), className?: string, aria-hidden?: boolean (défaut true)
  • Pas de couleur en dur → stroke="currentColor" hérite du texte parent
  • Tree-shaking : import nommé import { Flacon } from '@/components/icons'
  • Favicon : généré depuis flacon (32x32, 192x192, maskable 512x512)

9.3 Rendu

  • SSG par défaut pour toutes les pages marketing (build time)
  • ISR (revalidate: 3600) sur pages dépendant du CMS (collection, journal, maison)
  • Webhook Sanity → revalidatePath ciblé (tags: collection, journal, maison)
  • Pas de SSR hors API routes et formulaire RDV (Calendly embed client-side)
  • Streaming pour hero vidéo (Suspense boundary)

9.4 Images

  • Sanity Asset Pipeline (CDN) — transformation à la volée
  • Formats : WebP/AVIF auto, fallback JPEG/PNG
  • Responsive : next/image avec sizes adapté par composant
  • Hero : LQIP (blur-data-url) + priority=true
  • Lazy loading natif pour tout le reste
  • Poids max original : 2Mo (sanity validate), largeur max 2400px

ACCESSIBILITÉ (RGAA / WCAG 2.1 AA)

  • Contrastes : tous les textes AA (4.5:1), larges AAA (7:1) — l'or réservé aux éléments graphiques
  • Focus visible : outline 2px or, offset 2px sur tous les éléments interactifs
  • Navigation clavier complète : tab order logique, pièges à focus (modales, drawer), skip link
  • ARIA : landmarks (main, nav, aside, footer), labels formulaires, aria-hidden sur icônes décoratives
  • Images : alt pertinents, images décoratives alt="" + aria-hidden
  • Vidéos : sous-titres FR (VTT), transcription textuelle, pause auto hors viewport, pas de lecture auto son
  • Formulaires : labels visibles, messages d'erreur liés (aria-describedby), validation accessible
  • Responsive : zoom 200% sans perte de contenu, reflow vertical uniquement
  • Langue : lang="fr" sur html, changements de langue signalés (lang="en" sur termes techniques)
  • Mouvement : respect prefers-reduced-motion, pas de clignotement > 3Hz

  1. Audit automatisé : axe-core (CI) + Lighthouse Accessibility ≥ 95
  2. Test manuel clavier : parcours complet (tab, shift+tab, enter, espace, échap)
  3. Test lecteur d'écran : NVDA (Windows) + VoiceOver (macOS/iOS) — 5 scénarios critiques
  4. Test zoom 200% + 400% : vérification reflow, pas de troncature

SÉCURITÉ & RGPD

Sécurité

  • CSP strict via next.config.js : script-src 'self' 'nonce-...' https://cdn.calendly.com https://plausible.io, style-src 'self' 'unsafe-inline' (Tailwind), img-src 'self' data: https://cdn.sanity.io, font-src 'self' data:, connect-src 'self' https://api.resend.com https://plausible.io
  • Headers : X-Frame-Options: DENY, X-Content-Type-Options: nosniff, Referrer-Policy: strict-origin-when-cross-origin, Permissions-Policy: camera=(), microphone=(), geolocation=()
  • HSTS : Strict-Transport-Security: max-age=31536000; includeSubDomains; preload (Vercel géré)
  • Rate limiting API routes : 10 req/min/IP (contact), 5 req/min/IP (newsletter) — Upstash Redis ou Vercel Edge Config
  • Honeypot + timestamp sur formulaires (anti-bot sans CAPTCHA)
  • Validation Zod côté serveur sur toutes les API routes (jamais faire confiance au client)
  • Sanity : tokens lecture seule (CDN) pour frontend, tokens écriture (webhook) scope minimal, rotation trimestrielle

RGPD

  • Aucun cookie non essentiel — Plausible sans cookies, pas de GA, pas de Meta Pixel, pas de tracking tiers
  • Formulaires : consentement explicite case à cocher (RGPD + newsletter séparées), double opt-in email
  • Données stockées : Sanity (leads, RDV) — chiffrement au repos, accès restreint équipe projet
  • Resend : emails transactionnels uniquement, pas de marketing sans consentement, suppression logs 30 jours
  • Droit d'accès / rectification / suppression : page dédiée /donnees-personnelles + formulaire → suppression Sanity + logs sous 30 jours
  • Registre des traitements tenu à jour (responsable : client, sous-traitant : agence)
  • Mentions légales / Politique confidentialité / CGV : pages dédiées, liens footer, versionnées
